# LanguageToken — Social Good를 위한 Blockathon 2026

[English README](README.md)

[![tests](https://github.com/iamatownboy/ubc-blockathon2026-team2/actions/workflows/ci.yml/badge.svg)](https://github.com/iamatownboy/ubc-blockathon2026-team2/actions/workflows/ci.yml)

> **지역에서 배우고, 지역에서 얻고, 지역에 소속되세요.**

새로 이주한 사람이 3분짜리 실제 생활 영어 미션을 연습하고, 자신이 사는
동네의 가게에서 쓸 수 있는 기프트카드와 교환하는 양도 불가능한 크레딧을
얻습니다. 예를 들어 100크레딧으로 Tim Hortons 카드를 앱에서 받고, 그
카드는 사용자의 기기에 봉인됩니다. 코치는 누가 보상을 받을지 결정하지
않습니다. 온체인 원장에는 직접적인 개인정보가 없고, 크레딧은 정책이 아니라
설계상 현금이 될 수 없습니다.

이 프로젝트는 상위 폴더의 `LanguageToken Blockathon Plan.pdf`를 바탕으로
만들었습니다.

| 데모 목표 | 체인 | 제공사 |
|---|---|---|
| 미션 → 100크레딧 → Tim Hortons 카드 | 로컬 Hardhat, chainId 31337 (또는 메모리 원장 미러) | 실제 API 모양을 흉내 낸 목업 |

## 실행하기

```bash
node server/server.js
```

별도의 설치 과정은 없습니다. 프레임워크도, 의존성도 필요하지 않습니다.
이 명령은 **:8788**에서 목업 기프트카드 제공사를 시작하고(클라이언트가
실제로 네트워크 경계를 넘도록 별도 리스너를 사용합니다), 서비스는 **:8787**에서
시작합니다.

| 클라이언트 | URL | 설명 |
|---|---|---|
| 학습자 앱 | http://localhost:8787/learner/ | 430px 화면. 계정·이메일·지갑 프로그램·가스비가 없습니다. 파트너가 발급한 참여 코드(데모: `WELCOME-01` … `WELCOME-12`, 시작할 때 출력)가 세션을 엽니다. 기기는 카드를 받기 위한 ECDH 키 쌍(`extractable: false`)을 IndexedDB에 직접 만들며, 키는 기기 밖으로 나가지 않습니다. EN / 한국어 / 中文. |
| 검증자 콘솔 | http://localhost:8787/verifier/ | 검토 대기열입니다. 승인하면 미션에 설정된 금액이 지급되며, **금액을 입력하는 칸은 없습니다**. 토큰: `verifier-demo` |
| 관리자 콘솔 | http://localhost:8787/admin/ | 미션·카탈로그·일시정지·실시간 원장 이벤트·서비스 로그·제공사 장애 스위치를 관리합니다. 토큰: `admin-demo` |
| 데모 스테이지 | http://localhost:8787/demo/ | 심사 노트북용 화면입니다. 학습자 휴대폰 화면, 실시간 원장, 카탈로그 재고, 크레딧 보존 검사를 나란히 보여줍니다. 토큰이 필요 없는 두 API만 읽으므로 프로젝터 화면에 관리자 비밀값이 나타나지 않습니다. |
| 공개 통계 | http://localhost:8787/api/stats | 로그인 없이 누구나 읽을 수 있습니다. 집계 정보만 제공합니다. |

Node ≥ 20이 필요합니다(이 컴퓨터에서는 `. ~/.nvm/nvm.sh`).

선택 사항으로 `COACH=live ANTHROPIC_API_KEY=…`를 설정하면 실시간 코칭을
사용할 수 있습니다. 그래도 학습자가 명시적으로 동의해야만 연습 문장이
서비스 밖으로 전송됩니다. SDK는 `node_modules/` 또는
`web/node_modules/`에 있으면 사용하며, 루트에서 `npm install`을 실행하면
가져옵니다. 키가 없거나 API 호출이 실패하면 오프라인 코치가 데모를 계속
진행합니다.

### 누가 보상을 받을 수 있나요?

평생 한도는 브라우저가 아니라 *사람*을 제한해야 합니다. 새로 온 사람은
안정적인 휴대폰·이메일·신분증이 없는 경우가 많기 때문에, 이 프로그램은
파트너가 이미 관리하는 경계를 사용합니다. 도서관·정착 지원기관·학교가
종이 참여 코드를 나눠 줍니다.

서버는 코드를 저장하지 않습니다. 코드의 HMAC만 저장하고, 같은 HMAC에서
학습자 핸들을 만듭니다. 따라서 다음 세 가지가 모두 성립하며, 테스트도
세 가지를 모두 확인합니다.

* 발급되지 않은 코드는 세션을 전혀 열 수 없습니다.
* 브라우저 데이터를 지우고 코드를 다시 입력해도 같은 학습자로 돌아옵니다.
  잔액·완료한 미션·평생 한도가 같으므로, 브라우저를 지워서 두 번째
  기프트카드를 받는 방법이 통하지 않습니다.
* 서비스에는 이름·이메일·전화번호가 없습니다. 코드와 사람을 연결하는
  정보는 파트너 데스크의 종이에만 있습니다.

`ENROLLMENT_CODES`에 실제 코드 목록을 쉼표로 구분해 넣습니다. 데모 코드는
`NODE_ENV`가 `production`이 아닐 때만 존재하며, 코드 목록 없이 운영 모드로
시작하면 서버가 거부합니다. `ENROLLMENT=open`은 검사를 끄는 명시적이고
로그에 남는 선택이며, 한도를 기기 단위로 낮춥니다. 데모에 사용할 모드는
아닙니다.

코드는 낯선 사람과 기프트카드 사이의 유일한 문이므로 두 가지가 보호합니다.
`npm run codes 200`은 실제 엔트로피를 가진 코드를 출력합니다. `O/0/I/1`을
제외한 32글자 알파벳에서 8글자를 뽑아 40비트를 만들고, 자원봉사자가
읽어 줄 수 있도록 묶어서 보여줍니다. 잘못된 코드도 세어 주소 하나당
10분에 8번까지만 허용하며, 그 뒤에는 `retry-after`와 함께 `429`를 반환해
무한 추측을 막습니다. 맞는 코드를 입력하면 카운터를 지우므로 두 번 정도
실수한 학습자가 벌을 받지는 않습니다. 주소와 시도한 코드 자체는 저장하지
않고, 로그에는 사용한 시도 횟수만 기록합니다.

제한기는 프로세스 안에 있습니다. 여러 인스턴스 뒤에 배치하려면 공유
카운터가 필요합니다. 또한 프록시가 헤더를 설정한다고 `TRUST_PROXY=1`로
명시한 경우에만 `X-Forwarded-For`를 믿습니다. 그렇지 않으면 누구나 헤더로
자기 제한을 초기화할 수 있습니다.

학습자의 공개 키는 세션을 만들기 전에 실제 P-256 JWK로 파싱합니다. 잘못된
객체는 재고를 예약하거나 제공사에 주문하기 전에 거부됩니다. 관리자·검증자
역할 토큰은 요청 헤더로만 받습니다. 관리자 이벤트 스트림은 긴 수명의 역할
토큰을 1분짜리 일회용 티켓으로 바꾸므로 역할 토큰이 스트림 URL이나 브라우저
기록에 나타나지 않습니다.

### 누가 사용할 수 있나요?

학습자 앱은 언어·도시·손에 든 휴대폰 사용법이 모두 새로울 수 있는 사람을
위한 제품 전체입니다. 그래서 다음을 지킵니다.

* 문서의 언어를 실제 언어로 표시하고, 학습자가 언어를 바꾸면 함께 바꿉니다.
  그렇지 않으면 화면 읽기 프로그램이 한국어와 중국어를 영어 발음으로
  읽을 수 있습니다.
* 상태와 오류를 색깔만으로 표시하지 않고 알려 줍니다(`aria-live`, 오류는
  `assertive`).
* 화면을 바꾸면 포커스를 옮겨 새 화면을 읽게 합니다. 같은 화면을 다시
  그릴 때는 사용 중인 컨트롤에서 포커스를 빼앗지 않습니다.
* 글자 크기는 사용자의 브라우저 설정에 맞게 커집니다(`1rem`, 고정 픽셀
  크기 사용 안 함). 애니메이션은 `prefers-reduced-motion`을 따르고, 하단
  내비게이션은 48px 이상의 터치 영역을 갖습니다.
* 이모지는 장식으로 표시하고, 현재 탭은 `aria-current`로 표시합니다.

Test 12c3가 위 내용을 모두 고정합니다. 오른쪽에서 왼쪽으로 쓰는 언어를
위해 `dir`도 연결되어 있지만, 아직 번역된 RTL 언어는 없습니다. 이 문제는
코드 전체를 다시 쓰는 일이 아니라 문자열 파일을 추가하는 일입니다.

### 체인 모드

`LEDGER`를 설정하지 않으면 `shared/deployment.json`이 있을 때 서비스는
계약을 사용합니다. 체인이 정말 없거나 연결할 수 없을 때만 JS 미러
(`ledger.js`)로 돌아갑니다. 따라서 최종 데모는 기본적으로 온체인에서
실행되고, RPC가 죽어도 발표가 멈추지 않습니다. **현재 어떤 원장이 실행
중인지 모든 화면에 배지로 표시됩니다**(`On-chain` / `Demo mirror`). 따라서
미러 실행을 온체인이라고 잘못 보여주지 않습니다.
`LEDGER=chain`은 체인 연결 실패를 치명적 오류로 만들고,
`LEDGER=memory`는 미러를 강제로 사용합니다. 실제 계약으로 실행하려면:

```bash
cd contracts && npm install                                   # 최초 한 번
cd contracts && CHOKIDAR_USEPOLLING=1 npx hardhat node       # 터미널 1
cd contracts && npx hardhat run scripts/deploy.js --network localhost   # 터미널 2 → shared/deployment.json
LEDGER=chain node server/server.js                            # 터미널 3
```

`./reset-demo.sh`는 체인을 다시 시작하고, 계약을 배포하고, 서비스를 다시
시작합니다. 기본 메모리 원장 데모는 의도적으로 일시적입니다. 체인 모드에서는
가명화된 기기 공개 키와 봉인된 스왑 기록을 `.data/state.json`에 원자적으로
저장합니다. 시작할 때는 새 카드를 주문하지 않고, 보류 중인 제공사 요청을
조회해 복구합니다.

로컬 데모를 넘어서는 환경에서는 공개된 데모 값을 쓰지 말고 강한 비밀값을
설정하세요.

```bash
NODE_ENV=production \
IDENTITY_SECRET="$(openssl rand -base64 32)" \
ADMIN_TOKEN="$(openssl rand -base64 32)" \
VERIFIER_TOKEN="$(openssl rand -base64 32)" \
LEDGER=chain node server/server.js
```

운영 모드에서는 세 값이 각각 UTF-8 기준 32바이트 이상이어야 하고, 세 값이
서로 달라야 합니다. 약한 값·데모 값·재사용한 값이면 서버가 시작하지
않습니다. 실제 제공사를 사용하려면 제공사 온보딩, 프로그램·카탈로그 승인,
제공사의 실제 인증 설정도 필요합니다. URL 하나만 바꾸면 되는 일이 아닙니다.

## 테스트

```bash
npm test                          # 원장 28 + E2E 50 + UI 스모크 2 + 패리티 1
npm run test:parity               # 패리티만 실행(실행 중인 체인 필요)
cd contracts && npx hardhat test  # Solidity 23개(최초에는 네트워크로 컴파일러 필요)
cd contracts && SOLC_JS=1 npx hardhat test   # 같은 23개, 오프라인: node_modules의 solcjs 사용
```

`SOLC_JS=1`은 컴파일러를 내려받을 수 없거나 체크아웃 폴더에 쓸 수 없는
노트북을 위한 우회 방법입니다. 포함된 solcjs로 컴파일하고 빌드 결과는
`/tmp`에 둡니다. 두 방법 모두 23개가 통과합니다.

**원장, 28개 테스트.** 권한 없는 보상, ABI에 전달할 금액이 없는지, 중복
완료, 버전 증가, 횟수가 아니라 상한으로 적용되는 평생 한도, 잔액 부족,
재고 없음, 비활성 상품, 같은 잔액의 이중 스왑, 한 번만 가능한 정산,
정산 시 redeemer 키 거부, 크레딧과 재고를 정확히 되돌리는 취소, 만료·정리·
시계 연장, 보상은 막지만 환불은 허용하는 일시정지, 그리고 보존식
`awarded = outstanding + in-swap + swapped + expired`를 확인합니다.

**패리티, 1개 테스트 — 두 구현을 정직하게 유지하는 테스트입니다.** 계약과
JavaScript 미러는 같은 규칙을 두 번 구현한 것이므로 서로 달라질 수 있습니다.
`test/parity.test.js`는 보상, 중복, 스왑, 정산, 잔액 부족, 취소, 환불 사용,
잘못된 키를 두 원장에 똑같이 실행합니다. 매 단계에서 잔액·평생 합계·재고·
스왑 상태·보존식의 다섯 합계·revert 이름까지 전체 기록을 비교합니다.
체인이 없으면 이유를 크게 표시하고 건너뛰므로, 체인이 없는 노트북에서도
`npm test`가 동작합니다.

이 테스트가 실제 문제를 찾아냈습니다. `ChainLedger`는 각 역할 키를
ethers `NonceManager`로 감쌉니다. 그런데 학습자가 미션을 반복하거나
잔액이 부족한 스왑을 시도하는 것처럼 *예상된 revert*가 나도 로컬 nonce를
낙관적으로 증가시킬 수 있습니다. 그러면 이후 같은 키의 모든 호출이
`Nonce too high`로 실패합니다. 한 번의 중복 제출만으로 온체인 데모의
나머지 기간 동안 검증자 키가 멈출 수 있었습니다. 이 문제를 수정했고,
실행 중인 Hardhat 체인에서 패리티 테스트가 통과합니다.

**E2E, 50개 테스트.** 파트너 코드 없이는 세션이 거부되는지, 브라우저를
지워도 같은 핸들·잔액·평생 한도로 돌아오는지, 코드가 저장소에 나타나지
않는지, 코치 필터가 `pass`와 `credits`를 제거하는지, 변조한 제출이 보상을
주지 않는지, 채점과 검토 대기열, 검증자가 설정된 금액만 지급하고 요청의
금액 필드를 무시하는지, 모든 상품이 폐쇄형이고 개방형 상품은 거부되는지,
학습자 키가 카드를 열고 다른 키는 열지 못하는지, 제공사 잔액 API에서
카드가 실제로 확인되는지 검증합니다. 또한 확인된 제공사 실패의 환불,
응답이 사라진 주문과 HTTP 502 뒤의 주문을 재주문하지 않고 복구하는지,
해결되지 않은 제공사 결과를 환불 없이 `Requested`로 두는지, 만료된 검토를
직접 API로 승인할 수 없는지, URL의 역할 토큰을 거부하는지, 운영 비밀값
검사, 일시정지, 로그·이벤트 어디에도 카드 번호·PIN·이름이 없는지를
확인합니다. UI 스모크 테스트 2개는 작은 DOM에서 검증자 스크립트를 실행해
빈 대기열과 개인정보가 삭제된 완료 행을 모두 고정합니다. 따라서 정의되지
않은 헬퍼나 개인정보 정리 때문에 콘솔 전체가 비어 버리는 일을 다시 막습니다.

## 전체 흐름과 코치가 서면 안 되는 자리

1. 앱을 열고 파트너 데스크에서 받은 참여 코드를 입력합니다. 기기 키 쌍은
   브라우저에서 생성되고 밖으로 나가지 않습니다. 브라우저가 아니라 코드가
   학습자의 핸들·잔액·평생 한도를 정합니다.
2. 도서관·약국·학교 사무실 상황에서 세 가지 표현을 연습합니다.
3. 코치는 표현을 자연스럽게 고쳐 주고 이유를 학습자의 언어로 설명합니다.
   코치 출력은 네 필드의 허용 목록을 통과합니다. 오프라인 코치는 일부러
   `pass: true`, `credits: 999999`를 반환해 필터가 이 값을 제거하는지
   테스트할 수 있게 합니다.
4. 고정된 객관식과 필수 표현 검사가 통과·실패를 결정합니다. 표준
   proof-v2 해시는 두 답과 학습자가 쓴 시도를 묶지만, 어느 내용도 온체인에
   올리지 않습니다.
5. 통과하면 미션에 설정된 100크레딧을 지급합니다. 거의 맞았지만 실패한
   제출은 검증자 콘솔로 갑니다.
6. 상점을 엽니다. Tim Hortons, Save-On-Foods, TransLink, 지역 카페가
   크레딧 가격과 현재 재고를 보여 줍니다.
7. 교환을 누릅니다. 크레딧이 소각되고 재고가 줄어들며 스왑은 *Requested*
   상태로 열립니다.
8. 서비스는 스왑 자체의 해시를 멱등성 키로 사용해 상품을 주문합니다.
9. 카드가 돌아오면 학습자의 공개 키로 봉인하고, commitment만 정산합니다.
10. 카드가 마스킹된 지갑에 나타납니다. 공개하면 그 기기에서만 열리고,
    공개할 때마다 횟수가 기록됩니다.

## 설명하지 말고 직접 시연하기

관리자 콘솔에서 **ghost** 또는 **httpghost**를 켜고 학습자 앱에서 스왑을
실행하세요. 제공사는 카드를 발급한 뒤 응답을 버립니다. 클라이언트는
시간 초과 후 같은 request id로 제공사에 물어보고, 이미 존재하는 주문 한 건을
찾아 카드 한 장을 전달합니다. 관리자 로그에는 주문 한 건·정산 한 건·재고
한 단위만 남습니다. `httpghost`는 모호한 HTTP 502 뒤에도 같은 복구가 되는지
보여 줍니다.

타임아웃·5xx 뒤의 부정적인 조회는 제공사의 반영이 늦을 수 있으므로 최종
실패로 보지 않습니다. 주문을 찾으면 정산하고, 찾지 못하면 크레딧과 재고를
보류한 `Requested` 상태로 둡니다. 실제 제공사가 계약상 보장하는 명시적
최종 실패를 반환할 때까지 카드와 환불이 동시에 생기지 않습니다.

이어서 **declined**를 걸고 다시 교환해보세요. 이쪽이 나머지 절반이고, 학습자가
실제로 체감하는 쪽입니다. 발급사가 `422 order_declined`로 답하고, 주문은 생성되지
않았고, 다시 물어도 같은 답이므로 — 크레딧과 재고가 곧바로 돌아옵니다. 장면은 둘,
규칙은 하나입니다. *제공사가 실패했다고 말하면 환불하고, 아무 말도 하지 않으면
붙잡아 둔다.*

둘 중 어디에도 속하지 않는 교환이 있습니다. 제공사가 조용해진 뒤 끝내 돌아오지
않는 경우입니다. 이건 기계가 안전하게 종결할 수 없어서 사람이 합니다. 관리자
콘솔의 교환 표에서 Requested 상태에는 버튼이 **두 개** 있고 의미가 다릅니다 —
**reconcile**은 제공사에 다시 묻는 것이고, **refund**는 제공사가 뭐라고 했는지를
운영자가 단언하는 것입니다. 환불 라우트는 요청에 `confirmedNoOrder: true`가 없으면
거부하고, 실행 직전에 한 번 더 조회해서 주문이 나오면 환불 대신 카드를 전달하며,
`swap.force_refunded`로 그 결정을 기록에 남깁니다. 크레딧이 묶인 채로 두는 것은
신규 이민자에게 남겨둘 상태가 아니고, 그걸 끝내는 건 사람의 일입니다.

## 현금이 될 수 없는 이유

- 다른 학습자에게 보내기 — **transfer 함수가 없음**
- 거래소에 올리기 — **올릴 것이 없음**
- 개방형 Visa 카드로 바꾸기 — **카탈로그가 거부함**(`assertClosedLoop`, 테스트됨)
- 프로그램에서 현금으로 출금하기 — **법정화폐 통로가 없음**
- 카드를 공개하고 코드를 팔기 — *불가능하지는 않지만 어렵고 추적 가능*: 이메일로 보내지 않고, 기기에 봉인하며, 모든 공개 횟수를 기록함

## 심사위원이 먼저 찾기 전에 밝히는 한계

- 제공사는 목업입니다. 이 빌드에서는 실제 카드나 실제 카드 번호를 다루지 않습니다.
- 목업은 `4xx = 확정 실패`, `5xx/timeout = 모호한 결과`로 모델링합니다. 운영 전에는 계약한 제공사의 정확한 API 의미를 확인해야 합니다. 알 수 없는 결과는 운영자가 확인할 수 있도록 의도적으로 `Requested`에 남습니다.
- 검증자 키는 하나뿐입니다. 미션 레지스트리가 이 구조를 견딜 수 있게 할 뿐, 좋은 구조로 만들지는 않습니다.
- 데모 운영자가 모든 역할을 보유하고 모든 트랜잭션을 제출합니다.
- 만료는 lot가 아니라 계정 단위입니다.
- 메모리 원장 모드의 잔액은 의도적으로 사라집니다. 체인 모드에서는 기기 공개 키와 봉인된 스왑 상태만 저장하고, 세션 토큰과 학습자가 쓴 검토 문장은 디스크에 쓰지 않습니다.
- 통과·실패 제출은 구조화된 감사 결과를 남기지만 학습자 문장은 남기지 않습니다. 거의 맞은 제출은 검증자가 볼 수 있도록 최대 24시간 보관하고 결정 직후 삭제합니다. 패턴 검사는 명백한 개인정보를 줄이지만 자유 문장에서 개인정보를 완벽하게 찾아내지는 못합니다.
- 사람 단위 한도는 파트너의 코드 관리 수준만큼만 강합니다. 한 사람에게 코드 두 개를 주면 이 서비스에서는 두 명입니다. 데스크에서 한 사람당 코드 하나를 주고, 재발급된 코드를 폐기하는 배포 관리는 파트너의 책임이며 이 빌드가 강제할 수 없습니다. 실제 파일럿에서는 파트너 측에 코드 발급 기록을 추가해야 합니다.
- 카드는 코드를 마지막으로 사용한 기기 키에 봉인됩니다. 새 기기에서 코드를 다시 입력하면 잔액은 돌아오지만 이전 기기에 봉인된 카드는 열리지 않습니다. 이 사실은 지갑 화면에 숨기지 않고 표시합니다.
- 제한기는 한 프로세스의 메모리에 있습니다. 한 인스턴스 이상으로 확장하기에는 맞지 않는 크기입니다.
- `admin-demo` / `verifier-demo` 토큰은 이 문서와 콘솔에 공개되어 있으며, 사용 중이면 콘솔이 빨간색으로 표시합니다. 노트북에서만 사용하고 다른 곳에서는 사용하지 마세요. 운영 모드는 길고 서로 다른 값만 허용합니다. 역할 토큰은 헤더로만 받고, 실시간 이벤트 스트림은 짧은 수명의 일회용 티켓을 사용합니다.
- 작업 체크아웃에는 의존성과 빌드 결과가 약 1GB 있습니다. 추적하지는 않습니다. `./make-submission.sh`는 추적되는 소스와 lockfile만 내보내며(약 1.8MB, 55개 파일), 심사자가 직접 의존성을 설치합니다.
- 밴쿠버시·도서관·정착 지원기관·브랜드·제공사와의 제휴를 주장하지 않습니다.
- 체인은 학습이 실제로 일어났는지 확인할 수 없습니다. 검증자와 기준을 추적 가능하게 만들 뿐입니다.
