이제 도서관·정착지원기관·학교가 발급한 **종이 참여 코드의 HMAC에서 핸들을
파생**합니다.

- 발급되지 않은 코드는 세션 자체가 열리지 않음 (`403 enrollment_required` / `enrollment_invalid`)
- 브라우저를 지워도 같은 코드를 다시 입력하면 **같은 잔액·같은 완료 미션·같은 평생 한도**로 복귀
- 코드 원문은 저장·로그 어디에도 남지 않음 (HMAC만 보관). 이름·이메일·전화번호는 여전히 수집하지 않음
- 대소문자·공백·하이픈 무시 (`welcome 01` = `WELCOME-01`), 타이밍 공격 방지를 위해 상수 시간 비교
- 운영 모드(`NODE_ENV=production`)에서 `ENROLLMENT_CODES` 없이는 서버가 뜨지 않음
- 데모용 코드 `WELCOME-01` ~ `WELCOME-12`는 운영 모드가 아닐 때만 존재, 시작 시 콘솔 출력

**원장 모드 표시와 체인 우선 실행 (`server/ledger.js`)**

- `LEDGER=chain`은 체인 실패를 그대로 실패로, `LEDGER=memory`는 미러 강제

### `9a01256` — 두 원장 패리티 테스트, 그리고 그것이 찾아낸 버그

**`test/parity.test.js` (신규)**

컨트랙트와 JS 미러는 같은 규칙의 두 구현이고, 두 구현은 반드시 어긋납니다.
동일한 13단계 시나리오(지급 → 중복 거부 → 교환 → 정산 → 잔액 부족 → 취소 →
환불금 사용 → 잘못된 키)를 양쪽에 넣고 **단계마다 전체 상태를 비교**합니다:
잔액, 평생 합계, 재고, 교환 상태, 보존량 5개, 리버트 이름.

체인이 없으면 이유를 출력하며 건너뜁니다. 탐지에 타임아웃이 있어 `npm test`가
멈추지 않습니다.

**찾아낸 버그: 체인 모드에서 리버트 한 번이면 역할 키가 죽음**

`ChainLedger`는 각 역할 키를 ethers `NonceManager`로 감쌉니다. 이게 낙관적으로
nonce를 올리기 때문에, **정상적으로 리버트되는 호출**(학습자가 같은 미션을 두 번
제출, 크레딧 부족 상태의 교환 시도) 하나가 로컬 nonce를 태우고, 그 뒤 같은 키의
모든 트랜잭션이 `Nonce too high`로 실패합니다.

발표 시나리오: 심사 중 누군가 미션을 두 번 제출 → 검증자 키 사망 → **그 이후
아무도 크레딧을 받지 못함.** 체인 모드로 시연했다면 무대에서 터졌을 버그입니다.

`_send`가 실패 시 nonce 매니저를 리셋하도록 수정했습니다.

**추가:** `verifyLedger`의 체인 탐지에 4초 타임아웃. RPC가 연결만 받고 응답하지
않을 때 무한 대기 대신 미러로 폴백합니다.

### `11c32e2` — 팀 저장소(`upstream/main`, ca3d944)와 병합

작업 중 팀 쪽에 커밋 하나가 올라왔습니다: productCode를 해시가 아니라 ASCII를
bytes32로 packing해 체인에 저장하고, 관리자 콘솔에 "Sync from provider" 버튼을
붙인 변경입니다. 세 파일에서 충돌했고 다음과 같이 정리했습니다.

- **`server/catalog.js`** — 팀 버전 채택. `syncFromProvider`가
  `{accepted, refused}`를 돌려주고 승인 여부를 `listed`로 표시합니다. 우리 쪽은
  미승인 상품을 결과에서 아예 빼버렸는데, 승인 게이트는 sync가 아니라
  `POST /api/admin/catalog`에 있습니다(허용 목록에 없으면 `422
  unapproved_product`). 그래서 팀 버전을 쓰면 "제공사가 파는 것"과 "우리가 승인한
  것"이 화면에 함께 드러나면서 게이트는 그대로 유지됩니다.
- **`server/server.js`** — 우리 구조(메모리 모드 가드, 교환 복구, 참여 코드
  세션) 유지 + productCode 인코딩만 `asciiBytes32`로 통일.
- **`server/ids.js`** — `handleForPublicKey`와 `asciiBytes32` 둘 다 내보냄.

**여기서 조용히 깨질 뻔한 것:** 팀은 `deploy.js`(체인)와 `server.js`(미러)를 둘 다
바꿨지만, 한쪽만 바뀌었다면 체인은 텍스트를, 미러는 해시를 저장하고 어떤 테스트도
걸리지 않았을 겁니다. 그래서 **패리티 테스트가 productCode도 비교**하도록 했습니다.

**추가로 `listed:false` 경로를 실제로 살렸습니다.** 목업 제공사에 승인되지 않은
폐쇄형 상품 `PETROCAN-CA-2500`을 넣었습니다. 이제 관리자 콘솔 Sync 결과가
"우리 목록 4 · 미승인 1 · 거부 1"로 나오고, 테스트 `12a2`가 이를 고정합니다 —
폐쇄형이라 거부되지는 않지만, 미승인이고, 등록하려 하면 422로 막히고, 학습자
카탈로그에는 끝까지 나타나지 않습니다.
